# 历史报表与 SQL 兼容迁移策略

本项目当前采用“兼容优先、迁移可回滚、禁止自动删除”的策略。历史报表、历史计算字段和用户保存的原始 SQL 不在启动、构建或发布时自动改写。

## 当前规则

- 旧的 `AGG_DATE_*` 表达式继续按原规则生成 SQL，保证已有报表的字段类型和结果格式不变。
- 新建或重新选择日期层级时，只有 DATETIME 字段可以使用小时、分钟、秒和 `TIME_SLICE`。
- 复杂原始 SQL 的分页优先使用 AST 外包分页；解析失败时保留原 SQL，并使用数据库安全的兼容拼接，不修改数据库中的历史 SQL。
- 迁移失败只影响当前保存或当前查询，不阻塞历史报表打开。

当前已提供只读预览接口：

```http
GET /api/admin/history-migration/preview?orgId={组织ID}
```

接口要求组织管理员权限，只返回可管理资源的 ID、名称、类型和复核原因，不返回 SQL 明文，也不会写入任何表。

## 执行迁移前

管理员可在“组织设置 → 历史报表与 SQL 迁移 → 查看迁移预览”查看当前组织的只读扫描结果，也可调用 `GET /api/v1/admin/history-migration/preview?orgId=<组织ID>` 获取同样的数据。

1. 备份 Datart 元数据库和报表/分析配置。
2. 在测试环境导入备份，统计受影响的报表、图表、计算字段和原始 SQL 数量。
3. 只生成迁移预览，不直接执行删除或覆盖；预览至少包含资源 ID、原表达式、目标表达式、预计结果类型和失败原因。
4. 用管理员抽样验证日期字段、下钻、分页、下载和定时任务。

## 推荐迁移批次

1. 先只迁移新建日期层级的元数据，不触碰已有 `AGG_DATE_*` 字符串。
2. 再为可解析的原始 SQL 写入“已验证”标记；无法解析的 SQL 保持原样并记录原因。
3. 灰度运行一段时间，比较迁移前后的行数、列类型和错误摘要。
4. 只有业务确认后，人工执行归档；归档前保留资源导出文件和数据库备份。

## 明确禁止

- 启动时自动删除旧报表、旧 SQL、旧计算字段或旧函数配置。
- 构建脚本清理元数据库内容。
- 因新版本无法解析就覆盖历史 SQL。

后续如果需要真正清理，应在预览结果基础上单独提供带权限、确认、审计日志和回滚备份的管理员操作；当前仍不执行物理删除。
