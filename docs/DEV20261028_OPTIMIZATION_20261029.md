### 限流代理 IP 配置的注意事项

默认仅信任直接连接 Datart 的本地反向代理 IP：`127.0.0.1`、`::1`。
只有连接来自可信代理时才读取 `X-Forwarded-For` / `X-Real-IP`；从 XFF 右侧识别最近的非可信节点，避免直接使用可伪造的最左侧数据。

如果 Nginx/反向代理运行在另一台服务器，则需先确认其真实 IP 和请求头覆盖策略，在服务器自身的外部配置中设置 `datart.security.rate-limit.trusted-proxies`，并单独验收限流。请勿将任意互联网网段加入可信代理列表。**不要在此更改数据库、Token 或线上用户配置。**

### 批量查询回退的限额

保留现有 150ms 收集窗口、40 条/批、最多 2 个并行批次；对于确实缺失的返回项或 HTTP 404/405/501 的不兼容批量接口，单条回退每批最多 4 个并行请求。正常业务查询失败、权限拒绝、HTTP 500 不应被无条件重试；已经取消的 Widget 不应重入。

重要：这只是**并发上界**，不是性能改善的实测结论。还需要真实数据源、慢 SQL 和多 Widget 页面验证，不能将模拟单测当作生产吞吐量。

## 六、本轮追加优化（2026-10-29）

### 已按证据实施

- 查询追踪清理：对 `datart_query_trace.started_at` 自动补建单列索引。重启后的实际运行数据库已出现 `idx_datart_query_trace_started_at`，`EXPLAIN DELETE ... WHERE started_at < ?` 已使用 range 索引扫描，估算扫描约 1,343 行。
- 查询监控响应：每个数据源最多返回 50 条，总响应最多 200 条，避免多数据源或高频查询把管理页响应无限放大。
- 前端拆包：管理页、视图、数据源、成员、权限、调度、变量、仪表板、移动端、图表编辑器和故事页改为路由懒加载，并统一显示加载状态；第三方依赖仍保留单一 vendor chunk，避免历史循环依赖导致白屏。
- CSP：源码默认策略增加 `base-uri 'self'`、`form-action 'self'` 和 `object-src 'none'`，保留现有脚本兼容策略。当前运行包使用外部 `config/profiles/application-config.yml` 覆盖默认值，因此线上响应头仍需由部署配置单独调整。
- 兼容代码：只移除已确认无运行作用的注释和死注释，保留旧资源、迁移和分享仍可能依赖的兼容层。

### 真实业务 SQL 的边界

导入数据库的查询追踪显示“业务员拉新日报”两组 SQL 分别出现约 1113ms 和 950ms 的单次耗时。SQL 中存在未使用的 `p` CTE，且日期条件位于生成多表关联、聚合和窗口计算的外层；这类优化属于数据视图 SQL，需要连接实际 StarRocks 数据源执行 `EXPLAIN` 并对比结果后再修改，不能只改 Datart 后端源码推测。当前未修改报表内容和线上数据库。
